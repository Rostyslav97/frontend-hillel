## Компоненти

> Див. файл lesson-files/basic-component/src/components/Hello.jsx

```jsx
import React from 'react';

class Hello extends React.Component {
    render() {
        return <h3>Hello!</h3>;
    }
}

export default Hello;
```

Центральне поняття в React – компонент або функція. Більше того, це єдина сутність, яку він містить. Вся інша
функціональність побудована навколо компонентів.

У прикладі вище створений компонент, який додає `<div>Hello!</div>` до **DOM** сторінки.

Ось як виглядає отриманий **html**:

```html
<div id="root">
    <div class="App">
        <div>Hello!</div>
    </div>
</div>
```

Також компоненти можуть бути функціями

> Див. файл: lesson-files/basic-component/src/components/FuncComponent.jsx

```jsx
function FuncComponent(props) {
    return <h1>Привіт, {props.name}</h1>;
}

export default FuncComponent;
```

### Імпорти

Для того щоб описувати компоненти в різних файлах і потім використовувати їх в інших, ми будемо використовувати
es6 модулі і їх можливість експортувати функціонал з модуля і імпортувати в потрібному місці.

> Hello.jsx
```js
export default Hello;
```

> App.jsx
```js
import Hello from './components/Hello'
``` 

### Очевидні тези
Компонент React – це клас, який наслідується від класу React.Component (як ви побачите пізніше, це не єдиний
спосіб створити компонент). Функція render повертає щось (розглянемо пізніше), що буде відображено в браузері.
Клас-компонент без функції render існувати не може, це його інтерфейс. Експорт класу за замовчуванням заданий
не просто так. В JS прийнято створювати один клас на файл. На відміну від звичайних класів, React-компоненти мають
розширення JSX, а значить компонент, визначений вище, має лежати у файлі з іменем `Hello.jsx`.

Зверніть увагу: клас все одно іменований, хоча це і не обов'язково у випадку дефолтного експорту. Ви дійсно
можете його не іменувати, але тоді через розширення **React Dev Tools** буде важко зрозуміти, що ж відобразив React,
адже будь-який безіменний компонент відображається як `<ReactComponent>`. Тому візьміть собі за правило завжди давати
компонентам імена.


### Неочевидні тези

Найбільш вражаюче відбувається в цьому рядку:

```jsx
return <h3>Hello!</h3>;
```

Здоровий глузд підказує, що такий запис синтаксично неможливий в JS. І він буде правий. Те, що ви бачите,
називається **JSX** і є розширенням мови (додається за допомогою **Babel**). Кардинальне рішення для фреймворку,
чи не так? У процесі ви зрозумієте, що це не така вже й погана ідея.

Головне зараз запам'ятати те, що в кінцевому підсумку будь-який React-компонент повертає шматок **DOM** (насправді –
**віртуальний DOM**).

До речі, **div** – це теж компонент React, тільки вбудований. Відрізнити вбудовані компоненти від самописних дуже легко.
Вбудовані завжди починаються з маленької літери, а ті, які не є частиною React, повинні починатися з великої.

Гарним стилем вважається давати розширення `.jsx` для всіх файлів, які містять **JSX**, незалежно від того,
створюється чи ні компонент у цьому файлі.

### JSX
JSX – це схоже на XML-розмітку розширення для JavaScript, створене спеціально для завдань React. React з коробки
поставляється з набором компонентів, які повністю повторюють HTML. По більшій частині синтаксис і структура JSX і
HTML збігаються, але є деякі важливі відмінності:

Оскільки це схожий на XML синтаксис, одиночні теги в JSX мають бути закриті: <hr />.
- Замість атрибуту **class** в JSX використовується ім'я властивості в DOM: **className**.
- Існують і інші відмінності, про які ми поговоримо пізніше.
- Так само як і в HTML, з компонентів можна будувати композиції, наприклад таку:

```jsx
const vdom = (
  <div className="card">
    <div className="card-body">
      <h4 className="card-title">Card title</h4>
      <p className="card-text">my text</p>
      <a href="#" className="btn btn-primary">
        Go somewhere
      </a>
    </div>
  </div>
);
```

І це все валідний код на JS з підключеним розширенням для JSX.

Те, що кожен компонент React повертає шматок DOM, є наслідком його фундаментальної ідеї та архітектури.
Далі ми будемо розглядати детальніше цю ідею, і ви напевно проникнетеся нею. Але чому понадобилося вводити JSX?

Треба розуміти, що JSX – розширення мови, а значить це саме код, а не html. А якщо JSX транслюється в код, то,
відповідно, ви могли б одразу писати цей код. Правильно? Правильно, але не зовсім:

```js
React.createElement(
    "div",
    { className: "card" },
    React.createElement(
        "div",
        { className: "card-body" },
        React.createElement(
            "h4",
            { className: "card-title" },
            "Card title"
        ),
        React.createElement(
            "p",
            { className: "card-text" },
            "my text"
        ),
        React.createElement(
            "a",
            { href: "#", className: "btn btn-primary" },
            "Go somewhere"
        )
    )
);
```
Приклад коду вище – це саме те, як би виглядали функції **render** компонентів на React. Причому даний приклад дуже
тривіальний і не містить логіку. Якби у вас з'явилися умовні конструкції, то цей код перейшов би всі розумні
межі за складністю аналізу. На жаль, або на щастя, збирати древоподібні структури в коді (а DOM – це дерево)
– заняття дуже важке і безжальне. Тепер має стати трохи зрозуміліше, навіщо потрібен **JSX**, і що **JSX** –
це не верстка (як думають деякі).

Ну і останнє. Оскільки будь-який **JSX** в підсумку перетворюється транспілятором у виклики **React.createElement**, 
то потрібно стежити за тим, щоб React був імпортований:

```javascript
import React from 'react';
```
