# Дочірні елементи

UI-елементи мають ієрархічну структуру. Наприклад, компонент card у Bootstrap:

```html
<div class="card">
  <img class="card-img-top" src="..." alt="Card image cap">
  <div class="card-body">
    <h4 class="card-title">Card title</h4>
    <p class="card-text">
      Some quick example text to build on the card title and make up the bulk of the card's content.
    </p>
    <a href="#" class="btn btn-primary">Go somewhere</a>
  </div>
</div>
```

Блок картки може містити всередині себе зображення та тіло. Тіло, у свою чергу, може складатися з
заголовка та тексту, а текст може бути чим завгодно. Те саме застосовується як до найпростішої 
HTML-розмітки, наприклад, тегу <div>, так і до інших компонентів Bootstrap, таких як модальні
вікна та навігація.

HTML відповідає природі UI і природним чином дозволяє створювати композиції елементів за рахунок вкладення
тегів один в одного. Точно так само працює й JSX. Поки ця можливість використовувалася в курсі лише
для вбудованих компонентів. Тепер настав час навчитися повторювати подібну поведінку у власноруч 
написаних компонентах. Як приклад взятий компонент `<Alert />` з Bootstrap.

> lesson-files/children/index.html;

```html
<div class="alert alert-success" role="alert">
    <h4 class="alert-heading">Well done!</h4>
    <p>Aww yeah, you successfully read this important alert message. This example text is going to run a bit longer so that you can see how spacing within an alert works with this kind of content.</p>
    <hr>
    <p class="mb-0">Whenever you need to, be sure to use margin utilities to keep things nice and tidy.</p>
</div>
```

У наведеному вище прикладі обов'язковою частиною є лише основний div. Вміст залежить від конкретної ситуації.
Він підставляється за допомогою властивості children.

```jsx
// Alert.jsx

import React from "react";

class Alert extends React.Component {
    render() {
        const { children } = this.props;
        return (<div className="alert alert-primary">
            {children}
        </div>);
    }
}
export default Alert;
```

Зверніть увагу на те, що компонент почав використовуватися як парний тег у JSX:

```jsx
// App.js

<Alert>
    <h4 className="alert-heading">Well done!</h4>
    <p>
        Lorem ipsum dolor sit amet, consectetur adipisicing elit. Exercitationem,
        praesentium?
    </p>
</Alert>
```

Все, що знаходиться між відкриваючим і закриваючим тегом, потрапляє всередину пропса `children`.

Але будьте уважні: тип даних властивості `children` залежить від вмісту. У найпростішому випадку,
коли тег використовується як одиночний `<div />`, ця властивість буде дорівнювати `undefined`.

Якщо цим вмістом є рядок, то саме він опиниться всередині `children`. Проте після певної обробки.
**JSX** видаляє пробільні символи з початку та кінця рядка, включаючи порожні рядки.

Будь-який single дочірній компонент також буде представлений сам собою в `children`. У всіх інших
випадках `children` буде містити масив.

Якщо уважно подивитися на документацію React, можна побачити наступне визначення `children:
"children are an opaque data structure"` (властивість `children` — непрозора структура даних).
Іншими словами, неможливо однозначно покладатися на тип цього пропса, оскільки ззовні можна
передати все що завгодно.

Подібна поведінка може призводити до важкодоступних помилок. Наприклад, перевірка
`this.props.children.length` — це не завжди кількість дітей. Якщо `children` — це single елемент,
наприклад рядок, то властивість length поверне довжину цього рядка.

```jsx
class MyComponent extends React.Component {
  render() {
    const { children } = this.props
    return <p>Count: {children.length}</p>
  }
}

// <p>Count: 4</p>
<MyComponent>Text</MyComponent>
```

Саме тому React надає набір функцій, призначених для маніпулювання пропсом children. Всі вони 
доступні в `React.Children`. Ці функції знають про особливості роботи `children`, самі перевіряють
тип і виконують необхідні перевірки залежно від типу даних.

> lesson-files/examples/src/components/IgnoreFirstChild.jsx

```jsx
import React from "react";

class IgnoreFirstChild extends React.Component {
    render() {
        const { children } = this.props;
        return (<div>
            {React.Children.map(children, (child, i) => {
                // перший нащадок буде пропущений
                if (i < 1) return
                return child
            })}
        </div>);
    }
}

export default IgnoreFirstChild;
```

З уроку теми про колекцій ви можете згадати, що при роботі зі списком, кожному елементу потрібно
встановити проп `key`. Якщо цього не зробити у випадку з `React.Children.map`, React не видасть попередження.
Так зроблено навмисно, оскільки у нащадків зазвичай немає унікальних ідентифікаторів.

Крім перерахованого вище, іноді необхідно обробити дочірні елементи перед виведенням, змінивши
частину в **пропсі**. Звичайно ж, безпосередньо цього зробити неможливо, адже пропси незмінні. Тако
поведінки можна досягти, клонуючи елементи за допомогою функції `React.cloneElement()`.
